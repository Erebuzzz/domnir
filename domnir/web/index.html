    Dómnir Trust Boundaries & Architecture

    Non-Negotiable Trust Boundaries for Autonomous AI Flight Control

    01
    Host Never Runs Untrusted Code

    AI-generated flight controllers are restricted to an isolated Microsandbox microVM via /dev/kvm. The host simulation harness is strictly decoupled.

    02
    Secret Hygiene

    No Vultr Serverless Inference API keys, database credentials, or host secrets are ever passed into the guest execution cage or the frontend.

    03
    Host-Owned MuJoCo Simulation

    Only the trusted harness (Forseti) advances simulation physics, applies actuator bounds, and records truth telemetry. The guest only receives sensor observations.

    04
    Deterministic Replay Verification

    Recorded action vectors are replayed on a pristine MuJoCo instance to verify physical trajectory agreement within numerical tolerance (<= 1.00e-12 m difference).

    05
    Ephemeral Teardown Guarantee

    Every sandbox is subject to strict CPU, memory, and wall-clock deadlines. Cleanup and lease termination are enforced on normal and error paths.

    06
    Truth in Qualification

    Finite falsification campaigns identify boundary counterexamples. They are never represented as mathematical safety proofs or real-world airworthiness.

    Generated code executes exclusively inside ephemeral Microsandbox microVMs backed by AMD EPYC nested KVM (/dev/kvm). The guest runs under default-deny egress/ingress network policy, zero host mounts, 512 MiB memory limit, 1 vCPU, and a 0.50s monotonic watchdog ceiling.

    MuJoCo Simulation Dynamics

    The physical plant uses the official Bitcraze Crazyflie 2 model (cf2.xml, 27g mass, 92mm diagonal). The trusted host harness (Forseti) steps simulation physics at 500 Hz (dt = 0.002s) with RK4 integration. Actuator forces are clamped to the 0.35 N hardware saturation ceiling.

    06

    Understanding Falsification Results

    Verdict taxonomy strictly differentiates between FALSIFIED (boundary counterexample detected), NOT_FALSIFIED (no violations found under evaluated conditions), and INVALID (execution fault or divergence). A NOT_FALSIFIED outcome is synthetic qualification under tested parameters, not universal airworthiness proof.

    Review Verdict Criteria →
    07

    Replay Verification

    During flight trials, actuator action vectors are recorded at every timestep. To ensure physical reproducibility and rule out host state tampering, the recorded actions are replayed on a fresh MuJoCo instance. Replay is verified within declared numerical tolerance (≤ 1.00e-12 m).

    08

    Court Record Integrity

    Every experiment generates a self-contained, hash-linked Court Record JSON package. It contains SHA-256 digests of the controller source, plant XML, full trajectory coordinates, and a sequential host event hash chain from Genesis to Head. Verifiable offline without code re-execution.

    09

    Containment Evidence and Limitations

    Containment status is backed by verifiable host broker logs and network denial probes. Truthful disclosures clarify that memory termination is observed without speculative kernel OOM attribution, and event chains are locally hash-linked without external RFC 3161 timestamps.
